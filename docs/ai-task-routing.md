# AI 任务分流规则

按任务类型选择执行者。边界模糊时先 GPT；高风险先人工确认。

## 分流表

| 执行者 | 适合做什么 | 不适合 |
|--------|------------|--------|
| **GPT** | 需求澄清、任务拆解、方案比较、写验收标准、PR 总结 | 直接改仓库业务代码 |
| **Codex** | 任务明确后的仓库级修改、跑测试、修 CI、开 PR | 模糊需求下大范围猜测实现 |
| **Cursor** | IDE 内局部修改、调试、UI 调整、人工结对审查 | 替代 Codex 做整仓批量自动实现 |
| **人工** | 数据库迁移、支付、权限、安全、生产发布、用户数据处理 | — |

## 决策顺序

1. 需求是否清楚？否 → **GPT** 澄清并拆任务（用 `docs/task-template.md`）
2. 是否高风险（权限 / 支付 / 库表 / 用户数据 / 安全 / 生产发布）？是 → **人工确认** 后再执行
3. 改动是否整仓、跨多文件且任务已明确？是 → **Codex**
4. 是否局部、需边看边调、UI 或调试？是 → **Cursor**
5. 涉及迁移、支付、权限、安全、生产、用户数据执行本身 → **人工** 主导，AI 仅辅助准备材料

## 硬性约束

- 高风险任务必须人工确认后再执行
- 高风险任务必须先查看 `docs/risk-approval.md`
- 未填写「不做什么」和「验收标准」的任务，不进入 Codex / Cursor 实现
- 同一任务可「GPT 拆 → Codex 做 → Cursor 审」，但主执行者只能有一个
