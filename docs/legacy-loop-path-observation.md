# 旧三方闭环路径观察方案

> **性质**：路径迁移后的轻量观察计划（文档）。  
> **本轮不做**：创建 junction、删除旧路径、改 Documents 旁路、改动 AICF 业务仓。  
> 相关入口：根 [`README.md`](../README.md)「本地路径」表。

---

| 角色 | 路径 |
|------|------|

| **Legacy 副本（非主入口）** | `D:\三方闭环整合项目\` |

---

## 2. 当前处理策略

| 策略 | 说明 |
|------|------|
| 主入口 | 一律以新主仓为准（文档、Cursor 工作区、handoff、脚本） |
| Legacy | **保留**为只读倾向副本；不主动写入新闭环产物 |
| Junction | **暂不**创建（观察期后再议） |
| 删除 | **暂不**删除旧路径 |
| Documents 旁路 | **不改**；不把旁路仓当主仓 |
| 业务仓 | **不动** AICF 发布/脏态等 |

观察期建议：**1–2 天**（自本文落地日起算，或用户指定起始日）。

---

## 3. 观察什么

| 观察项 | 如何判断 |
|--------|----------|
| 是否误开 legacy | Cursor/终端/快捷方式/`cwd` 是否仍落在 `D:\三方闭环整合项目` |
| 是否误提交到旧树 | 旧路径下若仍是独立 git，是否出现新 commit（本方案不要求本轮检查 remote） |
| 新主仓是否稳定 | 新路径下日常 handoff / 文档任务可连续完成、无「找不到仓」类摩擦 |
| 文档入口是否够用 | README / handoff 默认入口是否已被使用 |

记录方式：可选在 `docs/pilot-log.md` 记一行 tip；**不强制**本轮改 pilot-log。

---

## 4. 触发后续处理的条件

满足**任一**可另开任务讨论处理（仍须用户确认后执行）：

1. **Legacy 仍被误用**（重复打开旧路径、在旧树改文件）  
2. **用户明确要求统一入口**（例如只要一个路径）  
3. **新主仓连续稳定**（观察期满且无路径混乱）

未触发则默认：**继续保留 legacy，不 junction、不删。**

---

## 5. 后续可选处理（仅方案，本轮不执行）

| 选项 | 说明 | 风险 |
|------|------|------|
| A. 保持只读副本 | 继续双路径；文档强调主仓 | 低；可能再误用 |
| B. Junction → 新主仓 | `D:\三方闭环整合项目` 改为指向新主仓的 junction/symlink | 中；须确认旧树无未备份独有改动 |
| C. 删除前先备份 | 打包/移走旧树后再删 | 中；不可逆，须备份校验 |

推荐顺序：观察期满 → 确认无独有未备份改动 → 用户授权 → 再选 A/B/C。
