# 风险与人工审批

把「高风险任务必须停在人工确认前」固化为可执行流程：分级、禁止动作、审批字段、回滚要求。

相关：[`docs/verification.md`](verification.md) · [`docs/ai-task-routing.md`](ai-task-routing.md) · [`PR_CHECKLIST.md`](../PR_CHECKLIST.md)

## 风险分级

| 等级 | 定义 |
|------|------|
| **低** | 文档、示例、文案、局部无损改动；失败易回滚，无数据/权限/资金影响 |
| **中** | 有源码或配置改动，可能影响行为或构建；可用测试覆盖，但需关注回归 |
| **高** | 触及数据、资金、权限、安全、生产或大范围不可逆变更；必须先人工审批 |

不确定时按**更高**一级处理，不得擅自降级。

## 高风险任务范围

出现以下任一情形，即按高风险处理（任务状态应为 `待确认`）：

- 数据库迁移
- 支付和财务逻辑
- 权限和安全策略
- 生产发布
- 用户数据处理
- 大规模重构

## 高风险任务禁止动作

**未人工确认前**，任何执行者（GPT / Codex / Cursor / 脚本）均不得：

- 修改相关代码
- 生成迁移文件
- 连接或修改数据库
- 发布生产
- 处理真实用户数据

允许：写任务单、补审批材料、做方案比较、在隔离环境用假数据讨论（不得触达真实库与生产）。

## 人工审批字段

高风险任务进入执行前，须留下可核对的审批记录（可写在任务单末尾或独立审批节）：

```markdown
## 人工审批记录

- 审批人：
- 审批时间：
- 审批范围：（批准哪些文件 / 环境 / 步骤）
- 允许执行的动作：
- 回滚方案：
- 备注：
```

缺任一关键字段（审批人、范围、允许动作、回滚方案）视为**未批准**，不得改为 `进行中`。

## 审批后执行

1. 仅执行「允许执行的动作」内的步骤；超范围须重新审批
2. 按 [`docs/verification.md`](verification.md) 高风险门槛验证
3. 合并 / 发布前再次确认回滚方案可执行
4. 完成后在任务单注明实际执行范围与是否动用回滚

## AI 执行要求

1. **识别风险等级**，写入任务单与交付说明
2. **高风险先停下**：状态保持 `待确认`，不改码、不迁库、不发布
3. **输出待确认项**：缺什么审批信息、影响数据/权限的哪些点
4. **不得擅自降级风险**；不得用「只是看看」绕过禁止动作
5. 审批记录不完整时，明确回复「等待人工确认」，而不是继续实现
