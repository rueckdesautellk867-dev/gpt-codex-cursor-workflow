# tasks/ 使用说明

本目录存放**可执行任务单**与总清单，把规则从「文档可用」推进到「任务执行可复用」。

字段模板见 [`docs/task-template.md`](../docs/task-template.md)；分流见 [`docs/ai-task-routing.md`](../docs/ai-task-routing.md)。

## 目录约定

| 路径 | 用途 |
|------|------|
| `tasks/backlog.md` | 总清单：编号、标题、风险、执行者、状态 |
| `tasks/T00x-*.md` | 单任务文件，一项一事 |
| `docs/examples/` | 示例（非执行队列）；真实执行用本目录 |

## 状态

| 状态 | 含义 |
|------|------|
| `待办` | 已写清边界，可领取 |
| `进行中` | 已有执行者在做 |
| `待确认` | 高风险或关键点，**人工确认前禁止执行** |
| `已完成` | 满足完成标准，结果已回流 |
| `已取消` | 不再做，须写明原因 |

## 新建任务

1. 复制 `docs/task-template.md` 字段，保存为 `tasks/T00x-简述.md`
2. 在 `backlog.md` 登记一行（状态默认可执行则为 `待办`；高风险则为 `待确认`）
3. 必须写清「不做什么」与「验收标准」，否则不得进入 Codex / Cursor 实现
4. 高风险（权限 / 支付 / 库表 / 用户数据 / 安全 / 生产）→ 状态设为 `待确认`

## 从任务单到合并（最短操作）

1. 在 `backlog.md` 领取任务，状态改为 `进行中`
2. 按任务单「影响范围 / 不做什么 / 验收标准」实现；只改相关文件
3. 跑任务单写明的测试 / 校验；高风险须已人工确认
4. 按 `PR_CHECKLIST.md` 与 `docs/definition-of-done.md` 自检
5. 开 PR / 提交说明：变更总结、验证结果、风险与待确认
6. 合并后：`backlog.md` 与任务单状态改为 `已完成`，必要时写入 `docs/pilot-log.md`
